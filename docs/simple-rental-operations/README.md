# Simple rental operations

Review and apply MAIN migration `202610260036_simple_rental_operations.sql` before confirming the new cash actions. It is prepared only and has not been executed. Existing manual/advanced operations continue to use their original functions; the new normal-operation wrapper fails closed until migration 036 exists.

Normal rental payment, cash deposit collection, and cash deposit refund use an explicit confirmation dialog with no editable amount, method, date or notes. The server requires a fresh active administrator session. The database locks the booking, recomputes the outstanding amount from its immutable ledger, rejects changed displayed amounts, and calls the existing payment/deposit function using cash and the current server timestamp. Timestamps are instants displayed in Asia/Manila; the authenticated administrator is recorded by the existing writers. Buttons are disabled during submission, stable idempotency keys protect retries, and a fresh concurrent request cannot exceed the locked remaining balance.

Motorcycle return opens the existing inspection workflow. The return step reads the recorded return inspection; completion remains separate and retains all existing requirements. Saving an inspection never automatically refunds money. Inspection notes can record damage, missing accessories, fuel and other charge observations. No observation silently creates a monetary charge.

The existing deposit ledger gains the `cash_deducted` decision type. Advanced deposit actions require a return inspection, a positive amount within remaining liability, an explicit reason, administrator confirmation and an immutable audited event. Deductions are neither cash refunds nor rental receipts. The normal refund dialog displays collected cash, approved deductions with reasons, prior cash returns, and remaining cash due. It refunds the remaining liability only after explicit cash-return confirmation. Existing partial-return policy and legacy custody operations are preserved. No old transaction or deposit snapshot is updated. The held-liability summaries and existing completion/handover calculations account for the new event type without altering identity requirements, notifications or payment integrations.
